# 매칭 상태 머신·스케줄러

## 문제 상황

문제 등록 후 강사 매칭은 여러 주체(학생·다수의 강사)가 비동기로 개입한다. 강사가 지원했는데 학생이 응답하지 않거나, 학생이 수락했는데 강사가 확인하지 않는 등 **한쪽이 응답하지 않아 매칭이 방치**되는 상황이 생긴다. 또 탐색 기간이 지난 문제를 자동으로 정리하지 않으면 강사 목록에 만료된 요청이 계속 남는다.

## 해결 방법

- 매칭 신청을 **명시적 상태 머신**으로 모델링했다: `PENDING → CONFIRMING → ACCEPTED`, 그리고 `REJECTED / UNAVAILABLE / EXPIRED / CANCELLED` 전이.
- **30초 주기 스케줄러**로 다음을 자동화했다:
  - **만료 임박 알림** — 탐색 마감 1시간 전 학생에게 안내(WebSocket 알림)
  - **만료 처리** — 마감 지난 문제를 EXPIRED로 전환하고 대기 중 신청을 만료 처리
  - **확정 타임아웃(5분)** — CONFIRMING 상태에서 양측 확인이 5분 내 안 되면 자동으로 PENDING 복구 후 알림
- 상태 전이와 알림을 스케줄러가 주기적으로 정리해, 사람이 개입하지 않아도 매칭 큐가 항상 정합성을 유지하도록 했다.

## 핵심 포인트

- 다자간 비동기 협상을 명시적 상태 머신으로 정리해 전이 규칙을 코드로 강제.
- 30초 스케줄러로 만료 임박/만료/확정 타임아웃을 자동 정리(방치 상태 제거).
- 실시간 알림(WebSocket)과 상태 전이를 연동해 사용자에게 즉시 피드백.

## 관련 코드/도메인

- `backend/.../domain/matching/` — `MatchingScheduler`(30초, checkExpiringSoon/checkExpired/checkConfirmingTimeout), `MatchingApplication`(`ApplicationStatus`), `MatchingNotificationService`
- `backend/.../domain/problem/` — `Problem`(탐색 마감/만료 상태)
- 실시간 알림: WebSocket/STOMP (`WebSocketConfig.java`)
